          - psychological: makes the `base` maintainers feel more in control.

**Example**:
* My library compiles with GHC 10.0, and base 22.7
* Then GHC 10.2 comes out,
  * Accompanied with base 22.7.8 which has some CPP so it can be compiled with with both 10.0 and 10.2.
  * Probably also comes with base-22.8.0 which has changes required by CLC since 10.0 release.
* Goal: compile my library with GHC 10.2, and base 22.7.8
* To achieve this, I would need my-library to have a version bound for base that allows minor version bumps.
* When 10.4 comes out, with base 22.9 (CLC changes), ideally we also release
    * base-22.7.9 so that it compiles with 10.0, 10.2 and 10.4
    * base-22.8.1 so that it compiles with 10.2 and 10.4
* At some point this becomes tiresome.
* All these versions of `base` must be tested.
* Suggestion: Limit scope by working with N previous GHC LTS versions and M previous non-LTS versions, N+M <=5
