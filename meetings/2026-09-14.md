# In progress projects

- Jappie: [hie library split(https://gitlab.haskell.org/jappeace/ghc/-/merge_requests/1)
  - Goal: separate library `ghc-hie`
       - Defines AST format (mirrors all of HsSyn in generic, rose-tree-like way), file format, and both serialisation and deserialisation, for HIE files
       - The code that *generates* a HIE file stays in GHC; GHC depends on `ghc-hie`
       - Other tools now depend only on `ghc-hie` not on `ghc`.
       - Changes in HsSyn don't necessarily force changes in HIE AST.
  - **Current work**: remove all GHC-specific data types from `HieAST` format.
  - We started over making something that we could merge, see [latest update](https://gitlab.haskell.org/ghc/ghc/-/issues/18329#note_660627)
      - Current issue: crashing on validation, we figured out where all the names were coming from. (There was a seperate name list for exports)
          - investigating why instances are removed from typeclass for this one specific test.
          - we mapped out the callstack, looks like the instances aren't in the AST
              - but they are in the AST on master
      - goal is to not have to bump hie versions across ghc versions.
          - with new data constructors within ghc we may have to bump versions if you can't map into the existing format
  - Action: **Jappie**
