# In progress projects

- Jappie: [hie library split(https://gitlab.haskell.org/jappeace/ghc/-/merge_requests/1)
  - Goal: separate library `ghc-hie`
       - Defines AST format (mirrors all of HsSyn in generic, rose-tree-like way), file format, and both serialisation and deserialisation, for HIE files
       - The code that *generates* a HIE file stays in GHC; GHC depends on `ghc-hie`
       - Other tools now depend only on `ghc-hie` not on `ghc`.
       - Changes in HsSyn don't necessarily force changes in HIE AST.
  - **Current work**: remove all GHC-specific data types from `HieAST` format.
  - We started over making something that we could merge, see [latest update](https://gitlab.haskell.org/ghc/ghc/-/issues/18329#note_660627)
      - Current issue: crashing on validation, we figured out where all the names were coming from. (There was a seperate name list for exports)
      - goal is to not have to bump hie versions across ghc versions.
          - with new data constructors within ghc we may have to bump versions if you can't map into the existing format

# New items

- **GHC release cycle**
  - https://discourse.haskell.org/t/ghc-9-14-2-rc1-is-now-available
  - https://discourse.haskell.org/t/ghc-9-12-5-rc3-is-now-available
  - How does GHC team feel about feedback on rc now?
      - Magnus has been coordinating with distributors. See: https://matrix.to/#/#haskell-distros:matrix.org

   - Many users wait for Stackage LTS releases.
   - Currently there is no Stackage LTS release for GHC 9.12, which itself was released in Dec 2024 (18 months ago)
   - Particularly long because of bugs in GHC 9.12.  These bugs are fixed in 9.12.5, due for release in August.  (Sad saga: one bug in 9.12.1 was fixed in 9.12.2, but 9.12.3 accidentally re-introduced the bug.  Unlikely to be repeated.)
   - GHC 9.14 released Dec 2025.  But Stackage LTSs lag one major release, so there is always a one-release delay.
   - GHC 10.0 should be released soon.
   - Problem for industial users.
       - Don't want to be stuck on an an un-maintained release.
       - But necessarily at least 12m+ behind releases
       - GHC LTS releases X-2, X-1, X.  Maintenance policy: maintain two (?) X, X-1.
       - Expect Stackage LTS depends on GHC LTS.

   - Example:
      - GHC LTS release X on 1 Jan 2026, maintained until 1 Jan 2028
      - GHC LTS release X+1 on 1 Jan 2027
      - GHC LTS release X+2 on 1 Jan 2028
      - Stackage LTS for GHC X will come out (say) Apr 2027, no earlier!
      - So the window in which we have a maintained GHC LTS and Stackage LTS is only 9 months: Apr-Dec 2027.
      - If GHC's LTS maintenance window was **three** years, the window would be 21 months; and an upgrade path exists for the final 9 months of that window.

   - Interestingly, we can't find GHC's LTS policy!
       - https://www.haskell.org/ghc/blog/20250702-ghc-release-schedules.html
