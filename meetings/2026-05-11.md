  - Working on blog post to describe project motivation and progress

      - Seek helpers ...
      - Criteria for success:
          - New GHC version comes with a minor release of base-5.6.8 that allows you to compile existing libraries with unchanged base version bounds (say base-5.6).
          - Provided you only depend on the new, stable TH interfaces
          - Provided you have not depended on the legacy GHC-internal APIs in base.

     **Andreas** will talk to Rodrigo.

  - Test suite being moved/decoupled
  - Shout about it more!  Release GHC 10.0 instead of 9.16
  - [Discussion on CLC ticket 375](https://github.com/haskell/core-libraries-committee/issues/375)
      - [Especially this comment which summarises the state of play ](https://github.com/haskell/core-libraries-committee/issues/375#issuecomment-3646780735)

  - Next steps:
      - Remove GHC-specific junk from `base` API.  Everyone agrees to do this.
      - Move as much as possible from `ghc-internal` to `base`.  Reasons:
          - doing so makes it easier to build shims; less to check.
          - maybe a technincal point too (Matthew will find out)
          - psychological: makes the `base` maintainers feel more in control.

    - A bunch of CLC proposals to remove GHC-specific stuff from `base`
    - About to release 10.0
    - Goal: when 10.2 comes, it comes with a 10.0-compatible base libarary; i.e. that you can compile with 10.2 an library with 10.0, which in turn depends on the base-version that comes with 10.0


    - Tevis's example:
        - GHC 10.8 comes with base-9.0.
        - Existing `base-8.2`, compilable with GHC 10.6.
        - Release `base-8.3`, with some but not all the changes that are in `base-9.0`
